## 已知问题

| 状态 | 描述 | 影响范围 | 复现步骤 |
|------|------|----------|----------|
| 已确认 2026-09-20（非缺陷） | 标称 HC-05 的模块实为 **BLE-only**（固件 `hc05V2.3_le`，无 BR/EDR 射频）。BLE 无 RFCOMM 层，Windows **永远不会**生成 COM 口，"配对成功但没串口"不是配置问题；也不能靠刷固件变经典蓝牙 | 全部蓝牙串口链路、pyserial 路线 | 设备枚举为 `BTHLE\DEV_21F6473AD889`，服务 FFE0/FFE1/FFE2；BTHENUM 无记录，全系统 `{00001101}` SPP 实例 0 个；`AT+VERSION?` 返回 `hc05V2.3_le` |
| 已修复 2026-09-20 | 模块出厂 `ROLE=1`（主机模式）→ 不响应 inquiry scan，手机和电脑**都搜不到**；但 LED 照闪、`STATE` 还报 `PAIRABLE`，极具迷惑性 | 配对连接 | `AT+ROLE?` 读回 1；置 `AT+ROLE=0` + `AT+RESET` 后即可被搜到 |
| 已修复 2026-09-20 | BLE 的 `FFE1` 只支持 **write-with-response**（bleak 属性名 `write`），`write_gatt_char(..., response=False)` 会**静默失败**：不抛异常也永远收不到回包 | 上位机所有下发命令 | 用 `response=False` 写 FFE1，日志中收不到 `OK`；改 `response=True` 即可 |
| 已修复 2026-09-20 | 扫描时写 `[d for d in res if d.name]` 会**把目标滤掉** —— BLE 名字在 scan response 包里，来得比主广播包晚 | 上位机设备列表 | 扫描窗口 6 秒时列表里没有 HC-05（同环境 15 秒能列出 45 个设备、目标在列，RSSI -63） |
| 已修复 2026-09-20 | 连接超时设 15s 恰好卡在实测中位数上（实测需 14.6~14.9s）→ 表现为"时通时不通"，很像模块坏了 | 上位机连接 | 反复连接成功率不稳定；改为 30s 超时 + UI 显示实时秒数后稳定 |
| 已加兜底 2026-09-20（根因在 WinRT） | 连错不可达设备（尤其 `51:53:xx` 这类随机地址的笔记本）会空等整个超时，失败后 WinRT 残留挂起操作，**连累后续扫描也不返回** | 上位机扫描/连接 | 连接失败后再点"扫描"或连第二个设备全无响应 → 对策：扫描/连接按钮互斥 + 每个协程 `asyncio.wait_for` 硬超时 + 【重置蓝牙栈】按钮（停旧 loop → `join(3)` → 新建 loop+线程，须在后台线程调用） |
| 已确认（设计使然，非 bug） | **1 档与 50 档速度差别很小**：占空比区间 28.0%~38.0%，比值仅 1.36 倍，本来就不明显 | 速度手感认知 | 报此现象时先对照 `Motor.h` 区间，勿怀疑 PWM 未生效；真判据是"退到 0 档电机必须停" |
| 待确认 | 电机**无编码器 → 无法自动检测堵转**，低速标定只能靠人眼 + 按键标记，人眼滞后 1~2% | `TUNE` 标定精度 | 观察 TUNE 下行占空比时电机是否停转 |
| 待确认 | `MOTOR_DUTY_MIN=280 (28.0%)` 是**设定值而非标定值**，1 档能否稳定维持未复测 | 低速档可用性 | 从 0 档启动（触发助推）后看 1 档是否连续转动、有无一顿一顿 |
| 待办 | 根目录文件**未归类**：`用户手册.pdf`、`build_log.txt`、`Project.uvguix.*` 与源码同级混放 | 可维护性、后续打包/上传 | 见 progress.md 待办第 2 条（范围待用户确认） |
| 待验证 | `TUNE` 标定的实机完整闭环（按按键标记 → 回 `TUNE DONE` → 1 档下限临时生效）未记录实测结果 | 标定功能可信度 | 发 `TUNE` → 等电机停住 → 按板上按键 → 看是否回 `TUNE MARK` 与 `TUNE DONE` |
